# AGENTS.md — Contributor and AI-Agent Guide

This file provides guidance for both human contributors and AI coding agents working on **FEs** — an F# client library for Elasticsearch.

---

## Project Overview

FEs generates a strongly-typed F# Elasticsearch client from the official Elasticsearch OpenAPI spec. The core library is in `src/Fes/`; auto-generated DSL types and operations live under `src/Fes/DSL/`.

**Key technologies**: F# 10, .NET 10, `System.Text.Json` + `FSharp.SystemTextJson`, xUnit, FSharpPlus (tests only).

---

## Repository Layout

```
src/
  Fes/
    Prelude.fs           – Utility functions (teeOk, teeError, konst, …)
    Task.fs              – TaskHelpers module (bind, map, retn, …)
    Result.fs            – Result module (retn, ofChoice)
    TaskResult.fs        – TaskResult<'a,'e> = Task<Result<'a,'e>> + combinators
    Exceptions.fs        – Elasticsearch error types and JSON converters
    Json.fs              – JsonSettings.options + Json/JsonRes helpers
    Http.fs              – Http.Request, Http.Response, ElasticsearchClient
    DSL/
      Models/Types.g.fs  – ⚠ AUTO-GENERATED (43 000+ lines) — do not edit by hand
      Operations/*.g.fs  – ⚠ AUTO-GENERATED — do not edit by hand
  Fes.Sample/            – Integration test / usage sample (run against live ES)
tests/
  Fes.Tests/             – xUnit unit tests
scripts/
  generate-dsl.fsx       – Code generator (reads scripts/esapi.2025-01.yaml)
```

> Files ending in `.g.fs` are auto-generated by `generate-dsl.fsx`. Never modify them manually.

## Building and Testing

```bash
dotnet build
dotnet test --no-build
dotnet run --project src/Fes.Sample  # requires live Elasticsearch at $FES_ES_SERVER
```

### ⚠ Known OOM Issue

The large auto-generated `Types.g.fs` (43 000+ lines) causes the F# compiler to OOM-kill (exit code 137) on memory-constrained CI runners. If `dotnet build` fails with exit code 137, this is an **infrastructure limitation**, not a code bug. The build does succeed in environments with ≥4 GB RAM.

When creating PRs, document infrastructure-caused build failures in the PR's **Test Status** section. Do not revert correct code changes because of this issue.

## Coding Conventions

- Match the style of adjacent code exactly.
- Use `[<JsonPropertyName("snake_case")>]` attributes on all record fields that are serialised to/from JSON.
- F# option types in JSON records require `JsonFSharpConverter` (already in `JsonSettings.options`).
- When adding new converters to `JsonSettings.options`, also add them to `ElasticsearchException.deserializeOptions` (which has a separate `JsonSerializerOptions` instance to break a circular dependency).
- Run `dotnet build` and `dotnet test` before creating any PR. If build fails only due to OOM, still create the PR but note the failure.

## AI Agent Guidelines

### Anti-Spam Rules

Previous automated runs created many duplicate issues and PRs. **Before creating any issue or PR**:

1. **Search open issues** for the same topic. There are already ~70 open issues, many of them duplicates.
2. **Check open PRs** (there are ~29 open Repo Assist draft PRs). If a PR already exists for your change, do not create another.
3. **Monthly Activity Summary**: there must be **exactly one** open `[Repo Assist] Monthly Activity {YYYY}-{MM}` issue at all times. Update it — never create a second one for the same month.

## Elasticsearch Compatibility

The generated DSL targets Elasticsearch **8.13** (the OpenAPI spec is `scripts/esapi.2025-01.yaml`). The CI docker-compose uses `elasticsearch:8.13.0`.
